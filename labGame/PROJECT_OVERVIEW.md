# Проект: Magic Laboratory (labGame)

## Общая логика проекта
Magic Laboratory — это игра-симулятор алхимической лаборатории, реализованная с использованием C++ и SFML. Игрок взаимодействует с ингредиентами, создает зелья, амулеты и выполняет заказы, используя графический интерфейс.

## Архитектура и ответственность классов

- **main.cpp** — точка входа, создает окно и основной контроллер (`GameController`).
- **controller/GameController** — главный контроллер, реализует логику взаимодействия пользователя с моделью и представлением. Обрабатывает события, управляет состояниями игры.
- **view/GameView** — отвечает за отрисовку всех элементов интерфейса, загрузку ресурсов (текстуры, шрифты), визуализацию состояния модели.
- **model/GameModel** — хранит и управляет основным состоянием игры: инвентарь, золото, уровни, активные заказы и т.д.
- **model/Item, Ingredient, Potion, Amulet, Star** — иерархия предметов. Базовый класс `Item`, от которого наследуются конкретные типы предметов.
- **model/Order** — описывает заказ (требуемые свойства предмета).
- **model/Factory, CloneFactory, Singleton** — паттерны для создания объектов (см. ниже).

## Взаимодействие между файлами
- `main.cpp` создает `GameController`.
- `GameController` содержит ссылку на `GameModel` (данные) и `GameView` (визуализация).
- Пользовательские действия (клики, ввод) обрабатываются в `GameController`, который изменяет `GameModel` и вызывает методы `GameView` для обновления экрана.
- `GameView` получает данные из `GameModel` для отрисовки.
- Все предметы (ингредиенты, зелья, амулеты) реализованы через наследование от `Item`.

## ООП-принципы
- **Наследование**: 
  - `Item` — базовый класс, от него наследуются `Ingredient`, `Potion`, `Amulet`, `Star`.
- **Полиморфизм**: 
  - Методы работы с предметами (`use`, `getProperties`, `getImageFile`) реализованы виртуально в `Item` и переопределяются в наследниках.
  - Использование умных указателей (`std::shared_ptr<Item>`) позволяет работать с коллекциями разнородных предметов через базовый интерфейс.
- **Инкапсуляция**: 
  - Все поля моделей и предметов скрыты, доступ только через методы.
- **Абстракция**: 
  - Интерфейсы предметов, фабрик, уровней абстрагируют детали реализации.

## Используемые паттерны проектирования
- **Factory Method**: 
  - Классы `Factory`, `ItemFactory` позволяют создавать объекты по строковому имени типа (например, "Potion", "Amulet").
- **Singleton**: 
  - `ItemFactory::Instance()` реализует синглтон для глобального доступа к фабрике предметов.
- **Prototype/Clone**: 
  - `CloneFactory` и методы `clone()` в предметах позволяют создавать копии объектов.
- **MVC (Model-View-Controller)**: 
  - Вся архитектура построена по принципу MVC: `GameModel` (данные), `GameView` (визуализация), `GameController` (логика и обработка событий).

## Singleton и фабрики: реализация и работа

### Singleton (Одиночка)
В проекте используется шаблонный класс `Singleton<T>`, который превращает любой тип в синглтон (глобальный единственный экземпляр):
- Пример: `ItemFactory::Instance()` возвращает глобальную фабрику предметов.
- Особенности реализации: статический метод `Instance()` возвращает ссылку на статический объект типа `T`. Конструктор и оператор копирования защищены, чтобы нельзя было создать второй экземпляр.

**Преимущества:**
- Гарантирует единственный экземпляр фабрики или менеджера.
- Удобен для глобального доступа к фабрикам без передачи указателей.

### Factory (Фабрика)
В проекте реализовано несколько фабрик для создания объектов по строковому имени или типу:
- **Factory** — шаблонный класс, хранящий ассоциации "имя типа" → "функция создания". Позволяет регистрировать новые типы и создавать объекты по имени.
  - Пример: `ItemFactoryType` — фабрика для предметов по имени (`std::string`).
  - Использование: `ItemFactory::Instance().CreateObject("Potion")` создаст зелье.
- **CloneFactory** — фабрика для клонирования объектов по типу (использует `typeid`). Позволяет создавать копии объектов, не зная их точного типа в момент компиляции.
  - Пример: `ItemCloneFactoryType`.

**Как работают фабрики:**
- При старте игры каждый класс-предмет (например, `Potion`, `Amulet`) регистрирует себя в фабрике через функцию-указатель.
- Когда нужно создать объект по имени, вызывается `CreateObject("Potion")` — фабрика ищет соответствующий конструктор и вызывает его.
- Для клонирования используется `CloneFactory`, где регистрация идет по `type_index`.

**Пример кода:**
```cpp
// Регистрация типа
ItemFactory::Instance().Register("Potion", []() { return std::make_shared<Potion>(); });
// Создание объекта
std::shared_ptr<Item> p = ItemFactory::Instance().CreateObject("Potion");
```

**Преимущества:**
- Гибкость: можно добавлять новые типы без изменения фабрики.
- Инкапсуляция: клиентский код не знает о деталях создания объектов.
- Поддержка полиморфизма: возвращается указатель на базовый класс.

**Связанные файлы:**
- `model/include/Factory.h` — шаблонная фабрика.
- `model/include/CloneFactory.h` — фабрика-клонер.
- `model/include/Singleton.h` — шаблон одиночки.
- `model/include/ItemFactories.h` — typedef-ы для фабрик предметов.
